**Targets 0800D630 and 0800D570 were already exact before this round.** They are internal labels of the installed garage/shop screen loop `func_0800D51C`, so this round installed no new replacement. The work was confirming that coverage, fixing the target ranking that kept listing these labels, and correcting the stale boundary note that led to them being assigned.

## Evidence

- `tools/rom.cfg` installs `func_0800D51C` at offset 0xD51C with **3,964 bytes**, covering **0800D51C–0800E498**, pools included. It was added on 2 November in commit 1a16ef6. `asm/program.s` contains only `.incbin build/leaves/func_0800D51C.bin` followed directly by `func_0800E498.bin`, so no assembly bytes remain anywhere in that range.

The source comment in `src/generated/func_0800D51C.c` already identifies them as the `reload`/`restart` labels and a loop-exit block. The ROM reaches them through long BL transfers, which are the far gotos in the C.
- The "stops after 84 bytes of initialization" note in `docs/asm-only.md` describes the registry's reachable extent up to the first long BL. It was written before 1a16ef6 and was never updated. Earlier breadth reviews (`near-misses/breadth-1112*/TARGETS.md`) had already recorded these labels as covered, but `tools/rank_targets.py` still ranked 0800D630 as an unmatched 3,662-byte target with 35 matched callees.

## Changes (branch work/finish-d630)

- `tools/rank_targets.py`: a new `covering_owner()` check reports any unmatched entry whose spans all fall inside an installed replacement's byte range as `covered by installed <owner>`, and skips the standalone checks for it. Ranked on worker C, 5 of the 48 unmatched entries are covered: 0800D570, 0800D630 and 0800D960 (by 0800D51C), 08007B40 (by 08007B28) and 080095C4 (by 08008A88). The other 43 entries are not inside any installed replacement. Some of them are themselves internal labels of the same uninstalled owners (for example 08003786 in 08002854, and the 080064A4 sound fragments), so there are fewer distinct owners left than entries.
- Tests: a synthetic fixture checks a covering owner and one that falls short by a single instruction (`tests/test_arm_rank.py`). A real-registry check asserts that the three garage-loop labels are covered (`tests/test_match4.py`).
- `docs/asm-only.md`: the 0800D51C boundary rows and the 0800D630 paragraph now point to the installed owner.
- The registry is unchanged on purpose. These entries are genuine BL-target control-flow entries that the native recompiler uses (237 functions / 268 load-run entries). Folding them into 0800D51C would change the native build without changing any matched byte. No map discovery was attempted, so unknown bytes stay at 719,822, and this round says nothing about whether the map is complete.
